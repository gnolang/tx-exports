# `gno.land/p/moul/printfdebugging`

> "this package is a joke... or not." (`printfdebugging.gno`, line 1)

Two functions for finding out whether your code reached a line, printed in a
color you cannot miss in a wall of test output.

```go
printfdebugging.BigRedLine("got here", "n =", "42")
printfdebugging.Success()
```

`BigRedLine` prints a full-width red bar with your arguments on it.
`Success()` prints a green one. That is the whole package.

It exists because `println` in the middle of a long `gno test -v` run is
invisible, and the fastest debugging tool is still the one that takes zero
setup.

## ANSI attributes

`color.gno` ships the SGR attribute set as typed constants, usable on their own:
`Reset`, `Bold`, `Faint`, `Italic`, `Underline`, `BlinkSlow`, `BlinkRapid`,
`ReverseVideo`, `Concealed`, `CrossedOut`, their `Reset*` counterparts, and the
foreground / background colors in both normal (`FgRed`, `BgBlue`) and
high-intensity (`FgHiRed`, `BgHiBlue`) variants.

Escape sequences are meaningless anywhere that is not a terminal. This is for
`gno test` output, never for a `Render` string.
