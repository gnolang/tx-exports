# `gno.land/p/nym-moultest123/mdlist`

> 🧪 **Proof of concept.** It explores a composable-UI idea rather than
> offering a settled API.

The idea: a realm should describe its data once and choose the presentation at
Render time, instead of building a different string for each layout.

```go
entries := mdlist.Entries{
	{Title: "First", Body: "Some text", Link: "/r/x:1"},
	{Title: "Second", Body: "More text", Link: "/r/x:2"},
}

out := entries.BulletList()       // or NumberedList, Paragraphs, Columns
```

| method | output |
| --- | --- |
| `BulletList()` | `- **Title** body` |
| `NumberedList()` | `1. **Title** body` |
| `Paragraphs()` | bold title, then the body as a paragraph |
| `Columns()` | a grid |
| `BulletListTruncated(t, b)` | as above, title and body cut to `t` / `b` runes |
| `NumberedListTruncated(t, b)` | same |

One `Entries` value, six renderings. A realm that stores its data as `Entries`
can switch layout from a query parameter, and a caller embedding that realm's
list can pick the shape that fits its own page.

Truncation takes explicit limits rather than guessing, because the right cut
depends on where the list is being embedded.
