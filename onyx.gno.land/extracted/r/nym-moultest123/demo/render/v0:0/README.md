# `gno.land/r/nym-moultest123/demo/render`

Step 4 of the `r/moul/demo` walkthrough: `Render`, the read-only view a realm
exposes to gnoweb.

```go
func Render(path string) string
```

`Render` receives whatever follows the `:` in the URL and routes on it. Three
routes are wired here:

| path | output |
| --- | --- |
| `""` | an index linking to the other two |
| `"hello"` | `Hello World!` |
| `"greetings/<name>"` | `Welcome, <Name>!` |
| anything else | `404` |

`Render` is a query, not a transaction: no gas, no signature, and it must be
deterministic.

```bash
gnokey query vm/qrender -data 'gno.land/r/nym-moultest123/demo/render:greetings/manfred' \
  -remote https://rpc.gno.land:443
```

**Caveat, kept on purpose.** The index route still emits links to
`/r/moul_basics_004:`, the path this code was written against in an older
workshop. They do not resolve at this realm's current path. It is a good
illustration of the trap: a hardcoded self-link becomes wrong the moment the
realm moves, so build links from the request path (see
[`p/moul/realmpath`](../../../../p/nym-moultest123/realmpath)) instead.
